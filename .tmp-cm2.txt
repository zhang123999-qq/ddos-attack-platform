fix(docker): align Dockerfiles with repo-root context; un-exclude deploy

Third GHA failure class on v1.2.0, in build-and-push: the workflow
builds with context=. (set when installer bundling was added), but:

1. .dockerignore still excluded deploy/ entirely, so COPY
   deploy/node-install.sh inside controller image could never resolve.
   Now only deploy/* is ignored with deploy/node-install.sh negated.

2. All three Dockerfiles began with a bare requirements COPY from the
   old per-directory context era; under root context that resolves to
   <root>/requirements.txt which does not exist (the exact
   "requirements.txt: not found" checksum error). Sources prefixed:
   controller/requirements.txt and attacker/requirements.txt.

3. Bonus: scenarios/ was dockerignored yet compose mounts it into the
   controller at /app/scenarios. Image now COPYs scenarios as an
   out-of-the-box fallback (mount still overrides).

All COPY sources statically verified to exist relative to repo root.
