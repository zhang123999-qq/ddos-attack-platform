## 🛡️ 核心安全原则

### 1. 仅限授权内网环境

- **严禁** 对未书面授权的目标发起任何攻击
- **严禁** 在生产网络、公共互联网、第三方网络中使用
- 仅允许在**隔离的实验网段**（如 `10.100.0.0/16`）内进行教学演练
- 实验网段必须**无互联网路由**，防止攻击流量意外泄露

### 2. 网络隔离要求（硬性指标，部署前必须验证）

| 要求 | 说明 | 验证方式 | 验证频率 |
|------|------|---------|---------|
| **独立 VLAN** | 攻击/靶机/控制网络物理或逻辑隔离 | 网络拓扑图 + VLAN 划分配置 + 交换机端口配置 | 部署前、变更后 |
| **无互联网路由** | 实验网段不可访问外网，防止意外泄露 | `traceroute 8.8.8.8` 应失败、`curl ifconfig.me` 超时 | 部署前、每日巡检 |
| **流量镜像** | 生产验证时使用镜像流量，非直接攻击 | 配置 SPAN/RSPAN 或 TAP 设备、镜像流量抓包对比 | 生产验证前 |
| **旁路部署** | 防御设备建议旁路/镜像模式，不串联核心链路 | 部署架构图确认、流量路径追踪 | 部署前 |

### 3. 权限最小化（强制执行，容器/系统层面保障）

| 组件 | 运行权限 | 必需 Capability | 禁止事项 | 验证命令 |
|------|---------|----------------|---------|---------|
| Controller | 普通用户 (UID 1000) | Docker socket 访问 | `--privileged`、root 运行 | `docker inspect --format '{{.HostConfig.Privileged}}'` |
| HTTP 攻击节点 | 普通用户 (UID 1000) | 无 | `--privileged`、`CAP_NET_RAW` | `docker inspect --format '{{.HostConfig.CapAdd}}'` |
| RAW 攻击节点 | 普通用户 (UID 1000) | `CAP_NET_RAW` | `--privileged`、`CAP_NET_ADMIN`（除非必要） | `getpcaps <pid>` |

> 💡 **最佳实践**：Docker 部署时使用 `cap_add: [NET_RAW]` 而非 `privileged: true`；systemd 部署使用 `CapabilityBoundingSet=CAP_NET_RAW`。

### 4. 熔断机制（三级保障，强制生效，不可禁用）

```
┌─────────────────────────────────────────────────────────────┐
│                    熔断触发条件                                │
├──────────────────┬──────────────────┬───────────────────────┤
│  管理员手动触发   │ 全局配额耗尽      │ 节点大规模离线 (>50%) │
│  POST /emergency  │ 自动拒绝新攻击    │ 90s 无心跳自动离线    │
└──────────────────┴──────────────────┴───────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                    熔断效果 (<100ms 生效)                    │
├─────────────────────────────────────────────────────────────┤
│  ✅ 拒绝所有新攻击指令                                        │
│  ✅ 广播 EMERGENCY_STOP 到所有在线节点                        │
│  ✅ 强制终止现有攻击任务                                      │
│  ✅ 释放所有速率配额                                          │
│  ✅ WebSocket 推送 critical 级告警                            │
│  ✅ 审计日志记录 emergency_stop 事件                          │
└─────────────────────────────────────────────────────────────┘
```

| 熔断类型 | 触发方式 | 生效时间 | 恢复方式 | 需授权角色 |
|---------|---------|---------|---------|-----------|
| 管理员手动 | `POST /api/v1/emergency_stop` | <100ms | 管理员 `POST /emergency_stop/reset` | 安全负责人 |
| 配额自动 | 超过 `GLOBAL_MAX_RPS/PPS` | 即时 | 配额释放后自动恢复 | 系统自动 |
| 超时自动 | 攻击持续时间到达 | 精确到秒 | 无需恢复，攻击自然结束 | 系统自动 |
| 心跳自动 | 节点 90s 无心跳 | 90s 后 | 节点重新注册 | 系统自动 |
| 审计失败 | 审计写入连续失败 | 即时 | 磁盘恢复/队列排空后自动重试 | 运维介入 |

### 5. 审计与不可抵赖

- **全链路结构化日志**：JSONL 格式，含时间戳、操作者、节点、攻击参数、结果、成败
- **日志保留**：≥ 90 天。实现说明——服务内置按大小轮转（100MB×10 份）+ 按天保留清理
  （`AUDIT_RETENTION_DAYS`，默认 90 天，每小时扫描过期轮转文件并删除）；
  满足 ≥90 天承诺仍建议接入 ELK/Splunk 集中归档
- **关键操作双人确认**：熔断触发、场景启动、证书轮换需两人以上授权
- **日志完整性**：禁止修改/删除审计日志，违者追责；建议启用 WORM 存储或区块链存证

## ✅ 部署前检查清单（逐项核对，缺一不可）

### 环境准备

- [ ] **书面授权文件**（盖章/签名，含授权网段、有效期、负责人、攻击类型清单）
- [ ] **实验网段 CIDR 确认**，已配置 `ALLOWED_TARGET_CIDRS` 环境变量（Controller 与所有 Attacker 一致）
- [ ] **网络隔离验证**：实验网段无法访问生产网/互联网（提供 `traceroute`、`curl` 测试截图）
- [ ] **证书生成**：`./deploy/generate_certs.sh` 已生成 CA + Controller + 所有节点证书
- [ ] **共享密钥生成**：`openssl rand -hex 32` 已写入 `SHARED_SECRET`，分发至所有节点

### 配置验证

- [ ] Controller `config.env` 所有必填项已填写（IP、端口、证书路径、密钥、白名单）
- [ ] 每个 Attacker `config.env` 匹配角色（HTTP/RAW）、攻击类型、资源限制（RPS/PPS/并发）
- [ ] 证书文件放置正确：`controller/certs/`、`attacker/certs/`，权限 600/644
- [ ] 端口无冲突：Controller `8443`、Attacker `8080`、Grafana `3000`、Prometheus `9090`

### 功能测试（必须全部通过）

- [ ] Controller 健康检查通过：`curl -k https://<ctrl>:8443/health`
- [ ] 节点注册成功：Controller `/api/v1/nodes` 可见所有在线节点
- [ ] 心跳正常：WebSocket `/ws/metrics` 持续收到节点心跳（含 CPU/内存/网络）
- [ ] **熔断测试**：触发 `/api/v1/emergency_stop` → 所有攻击 <100ms 停止
- [ ] **白名单测试**：攻击非白名单 IP → 被拒绝并记录审计日志

### 应急预案（必须文档化）

- [ ] 物理/逻辑断网开关位置确认、操作人员知晓
- [ ] 攻击失控回滚流程（含联系人、电话、操作步骤、预计恢复时间）
- [ ] 靶机业务降级/熔断方案已就绪
- [ ] 监控告警配置：攻击流量超阈值、节点离线、熔断触发 → 即时通知

### 参数调整原则（红线）

| 原则 | 要求 | 违规后果 |
|------|------|---------|
| 单次调整幅度 | ≤ 2 倍（RPS、并发、时长） | 记过、暂停操作权限 |

## 🔐 证书与密钥管理规范

| 文件 | 存放位置 | 权限 | 轮换周期 | 备注 |
|------|---------|------|---------|------|
| CA 密钥 | **离线冷存储**（加密U盘/硬件密钥/HSM） | 600 | 2 年 | 严禁上网设备存储，双人管控 |
| CA 证书 | 所有节点 `/certs/ca-cert.pem` | 644 | 2 年 | 可公开分发 |
| Controller 密钥 | `controller/certs/controller-key.pem` | 600 | 1 年 | 仅 Controller 读取 |
| Controller 证书 | `controller/certs/controller-cert.pem` | 644 | 1 年 | 节点验证用 |
| 节点密钥 | `attacker/certs/node-key.pem` | 600 | 1 年 | 每节点唯一 |
| 节点证书 | `attacker/certs/node-cert.pem` | 644 | 1 年 | Controller 验证用 |
| SHARED_SECRET | 密码管理器 / 环境变量（如 HashiCorp Vault） | - | 90 天（人工轮换） | **严禁写入代码/配置文件/镜像**。注：平台不强制过期——90 天为人工轮换纪律，轮换时须全节点同步更新并重启；生产镜像开启 `REQUIRE_SHARED_SECRET=true` 拒绝弱/默认密钥启动 |
| Enroll Token (v1.2) | 派生值，不落盘存储 | - | ≤2 小时（自动过期） | 由 SHARED_SECRET 经 HMAC 派生并绑定单节点 ID，仅用于节点自助接入时换取运行配置；服务端零存储、失败限速、全程审计。**不产生新的需保管的秘密**——安全性完全依附 SHARED_SECRET |

### 泄露应急响应流程（SLA：发现后 15 分钟内启动）

```
发现泄露 
    → 立即全网熔断 (POST /emergency_stop) 
    → 通知安全负责人
    → 吊销 CA (更新 CRL/OCSP) 
    → 重新生成全套证书 (generate_certs.sh)
    → 分发新证书 (distribute-certs.sh) 
    → 滚动重启所有节点
    → 验证所有节点重新注册、心跳正常 
    → 解除熔断 
    → 事后复盘报告（根因、影响、整改、责任人）
```
